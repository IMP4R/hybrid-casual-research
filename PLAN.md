## 1. Как здесь будет работать «просмотр» YouTube

Прямого видеопотока модель не видит. Реальная механика:

```
yt-dlp  ──> аудио/субтитры (авто-капшены) ──> текст повествования (кто, что, цифры)
        └─> видео 480p ──> ffmpeg (scene detect / fps=0.25..1) ──> 30–80 ключевых кадров PNG
                                                                    │
                                              агент смотрит кадры глазами (vision) ◄┘
```

Для @thenextbiggames нужны ОБА слоя: рассказчик проговаривает названия игр, жанры, метрики revenue/загрузок; кадры показывают сам геймплей и UI.

Следующий шаг удобства: собрать маленькую команду/плагин `watch_youtube <url>` → возвращает транскрипт + сетку кадров одним вызовом, чтобы анализ не был ручной вознёй.

## 2. Источник анализа: что показал зонд канала

Контент канала делится на 4 типа:
1. **Разборы трендов** («Hybrid Casual Trends May/June/July 2026», «10 HybridCasual Puzzle Trends», «14 Puzzle Trends 2026H1») — концентрат того, что нам нужно.
2. **Ад-тренды / креативы** (fake ads, hooks) — источник понимания первого впечатления за 1 секунду.
3. **Топы-обзоры** («TOP 28 Highest Grossing HybridCasual Puzzles 2025») — готовые списки тайтлов для декомпозиции.
4. **Новости M&A/финансирования** — второстепенно, фон рынка.

⚠️ Стратегически важная находка: у автора канала **уже существует nextbigideas.ai** — «AI tool generating 100,000 game ideas», плюс его манифест «Stop Inventing Mechanics. Clone Them Better». Это значит: комбинаторная генерация идей в этой нише НЕ свободна. Наша отстройка (см. §6): глубокая онтология + детерминированная валидация играбельности + доведение до готового Godot-билда, а не списки текстовых питчей.

## 3. Phase A (текущая): декомпозиция чужих игр

Вход: ссылка на видео канала или страницу игры в сторе.
Выход: **карточка механики** — строгий JSON. Схема v0:

```json
{
  "game": "...",
  "source_evidence": [{"video_ts": "03:12", "note": "увидено в кадре"}],
  "input_verb": "one_finger_drag | tap_timing | slice | hold_release | flick",
  "physics_material": "softbody | granular | rigid_stackable | elastic_tension | ...",
  "spatial_topology": "conveyor | grid_collapse | funnel_flow | radial_shrink | free_field",
  "tension_vectors": ["overflow_buffer", "wrong_color_penalty", "timer", "path_blocked"],
  "reward_loop": {"juice": ["combo_mult", "screen_clear"], "fail_condition": "..."},
  "modifiers_per_levels": ["frozen_blocks", "portals", "switches"],
  "meta_layer": "collection | base_build | none",
  "monetization_hooks": [...],
  "session_shape_seconds": 15,
  "browser_feasibility": {"webgl_draw_calls": "low", "sim_type": "shader|cpu", "risk": ""}
}
```

Правила детерминизма (первый набор инвариантов — «строгий философский слой» в духе разговора про графы):
- R1: НЕ предлагать ввод силой нажатия (force touch) — на большинстве телефонов его нет (урок разбора секонд-хенда).
- R2: ровно ОДИН кор-глагол у ядра; всё остальное — модификаторы уровней.
- R3: векторы напряжения не должны взаимоуничтожаться (ASMR-релакс ≠ тикающий таймер, пока нет дизайн-ответа на конфликт).
- R4: «до/после», шейдерные эффекты — не считаются геймплейной инновацией (маркетинговая косметика).
- R5: браузерное ограничение: симуляция >500 физических тел одновременно = CPU-риск; желателен shader-side sim.

Хранилище сейчас: SQLite/JSONL (таблица совместимостей механик 1/0). Графовая СУБД НЕ обязательна — нужна семантика графа, не Neo4j.

Вывод: ₽100 на игру достижимо, если 90% объёма — процедурные варианты поверх небольшой базы уникальных генераций, 3D берётся из CC0-китов, а не генерируется потоком.

QC-петля: каждый батч сгенерированных картинок проходит визуальный контроль агентом (сеткой кадров) — брак отсекается до попадания в игру.

Двухуровневая генерация (как задумано): широкий внешний LLM-апи рисует концепт целиком → локально VLM разбирает его на составляющие элементы → элементные промпты уходят в дешёвый генератор ассетов.

## 5. Phase D (позже): Godot-рантайм

- Шаблон проекта = буквальное воплощение формулы: слоты `[core_input] [conflict_system] [modifier_pack] [juice_kit]`, новые игры = конфигурация слотов, не новый код.
- Веб-экспорт Godot 4.x: wasm+pck — держать бюджет ~20–30 MB на загрузку; WebGL2; без threading-излишеств; симуляции сыпучего/мягкого — по возможности WGSL/compute или CPU-lite.
- Дистрибуция: **Яндекс Игры — первый таргет**, затем Poki и CrazyGames. Не аппсторы.
- Яндекс Игры специфика: ZIP с index.html (статический хостинг), модерация; Yandex Games SDK (JS) — interstitial/rewarded реклама, лидерборды, облачные сейвы; монетизация через RSYA; RU-трафик, рублёвая выручка. Для Godot: обёртка SDK через JavaScriptBridge поверх веб-экспорта.
- Веб-сборка под Яндекс: однопоточная, без требований SharedArrayBuffer; вес билда держать минимальным (первая цель < 25 MB).

## 6. Позиционирование против nextbigideas.ai

Они: списки текстовых идей по трендам (генератор, продукт для подписчиков).
Мы: замкнутый производственный конвейер — анализ → онтология с правилами → отбор → активы → рабочий билд Godot. Ценность там, где у них пусто: валидация играбельности и собственно производство игры.

✅ Проверено на практике: описания видео — сами по себе готовые досье (игра, паблишер, выручка, загрузки, суть механики, таймкоды). Видео целиком смотрим ТОЛЬКО точечно для спорных механик; основной источник — текст. Выжимка 16 роликов: `research/thenextbiggames_descriptions.md` → seed-библиотека `research/games_seed.csv` (41 уникальная игра, 35 с выручкой).

Очередь текстовых источников (богатые данными сайты): substack автора канала (vamsinextbiggames.substack.com), mobilegamer.biz, pocketgamer.biz, Deconstructor of Fun, GameDiscoverCo, блоги AppMagic / SensorTower, Meta Ad Library и TikTok Creative Center (креативы = опережающие тренды).

Инструмент досье v3 (готов): `tools/fetch_game.py "Game Name"` → `research/screens/<slug>/` — описания геймплея (App Store + Google Play) и галереи кадров: iTunes API, карусель Google Play, YouTube-миниатюры геймплейных роликов, обложка+mp4-кадры CrazyGames (веб-порты). Сводка в `DOSSIER.md`, каждая картинка дальше верифицируется агентом глазами.

Матрица источников (проверено боем 2026-08-27):
- ✅ iTunes Search API — описание разработчика + 6 скринов, свободный JSON
- ✅ Google Play — curl проходит; скриншоты = топовые play-lh хеши по частоте встречаемости (исключая og:image-иконку, валидация >20 KB)
- ✅ YouTube-миниатюры — чистый геймплей без маркетинговых плашек
- ✅ CrazyGames API — публичный JSON: обложки + mp4-геймплей → ffmpeg-кадры (для игр с веб-портом)
- ❌ Пиратские зеркала (apkpure, apkmirror, rexdl, apkfab, happymod, mobygames) — Cloudflare 403; APKCombo отдаёт только иконку (скрины под JS); appstorespy не нашёл app-страницу. Ключевое: зеркала лишь переносят те же play-lh картинки Google Play — прямой источник лучше. Для снятых с публикации игр — Wayback Machine по странице Play.
- ❌ Яндекс Игры как источник анализа — убран по решению пользователя (слабый контент). Остаётся целевой площадкой дистрибуции (§5).
