# Paint Loop (гипотеза Г1) — дизайн-док v2.0 (полный; база v1.1 от 2026-08-27)

Скелет S1 «Канва + Питатели» (рынок доказан на $189M: Pixel Flow + Yarn Loop + Sand Loop),
материал = **жидкая краска** (в топах не занято).

**Одной фразой:** заливай пиксель-картину жидкой краской — тапай вёдра в правильном порядке,
струя течёт из диспенсера в подсвеченную зону, не переполняй зоны и не лей чужой цвет.

**Почему жидкость — отличие, а не косметика:** перелив через бортик (объём конечен — у песка
этого нет), заполненная зона закупоривает канал (порядок = головоломка), капля чужого цвета
портит глянец (штраф читается мгновенно), глянец и капля в воздухе продаются в CPI без слов.

## 1. Ядро — ровно один кор-глагол (B5)

`tap_bucket_to_pour` — тап по ведру = ОДНА порция этого цвета летит по шлангу в диспенсер
и капает в ТЕКУЩУЮ подсвеченную зону. Тапать можно подряд; анимация капли (0.4с) ввод
не блокирует. Других постоянных глаголов НЕТ:

| Не глагол | Почему |
|---|---|
| тап/выбор самой зоны | зону выбирает только подсветка, игрок её не переключает |
| свайп, drag, hold-to-pour, force-touch | в ядре отсутствуют (§13) |
| смывка | тот же глагол: 3 тапа по белому ведру (§5) |
| раскрытие «?» | побочный эффект того же тапа (§6) |
| замок / канал / двойная зона | модификаторы маршрутизации, срабатывают автоматически (§7) |
| откат / подсказка / extra-смывка | rewarded-кнопки мета-слоя, вне игрового ядра (§11) |

## 2. Экран, зоны, вёдра
- Канва с пиксель-картиной разбита на зоны. У каждой зоны: **свотч требуемого цвета**
  в углу + **счётчик объёма (7/10)**.
- РОВНО ОДНА зона подсвечена — текущая. **Порядок зон = порядок подсветки**
  (слева направо, снизу вверх; модификатор «канал» делает порядок топологическим, §7).
- Вёдра-питатели внизу: 4–6 шт, у каждого видимый счётчик порций (22, 16, …).
  Палитра: синий, оранжевый, зелёный, красный, жёлтый, фиолетовый.
- Пустое ведро не исчезает — остаётся бутылкой-препятствием (декор маршрута).

## 3. Игровой цикл (секунда экрана)
1. Тап по ведру → капля летит по шлангу → падает в текущую (подсвеченную) зону.
2. Счётчик зоны растёт (6/10 → 7/10), счётчик ведра падает (20→19).
3. Зона набрала объём (N/N) → закрашена, окно смены подсветки 0.5с → подсвечена следующая.
4. Тап мимо (полная зона / чужой цвет) → штрафы, §4.

## 4. Пролив: два случая, точные штрафы
| # | Случай | Условие | Штраф (точный) |
|---|---|---|---|
| П1 | тап в полную зону | текущая зона уже N/N (спам-тап или повторный тап в окне смены подсветки 0.5с) | порция сгорает (ведро −1) + **1 пятно** на холсте |
| П2 | чужой цвет | цвет ведра ≠ свотч текущей НЕПОЛНОЙ зоны | порция сгорает (ведро −1) + **1 пятно** + **зона испорчена** → нужна смывка (§5) |

- Пятно = минус звезда (§8). Сгоревшей порции без пятна не бывает: П1/П2 всегда дают пятно.
- Испорченная зона: счётчик заморожен, подсветка с неё не уходит, заливка невозможна
  до отмывки.
- **Провал уровня:** цветные порции всех вёдер = 0 при незаполненных зонах, либо осталась
  испорченная зона при пустом белом ведре.
- **Победа:** все зоны верным цветом до полного объёма; звёзды по чистоте холста.

## 5. Смывка
- **Белое ведро: 1 на уровень, внутри 3 порции.** Активно только когда текущая зона
  испорчена (иначе затемнено, тапы не принимаются).
- **Отмывка = 3 тапа по белому ведру** (тот же кор-глагол): белая пена, счётчик зоны → 0,
  свотч снова активен; зону заливают заново с нуля.
- Смывка потрачена → 3★ недостижима (§8). Вторая смывка за уровень — только rewarded (§11).

## 6. «?»-вёдра
- Часть вёдер помечена «?» вместо цвета. **Цвет раскрывается при первом тапе** по ведру
  (в момент заливки).
- Риск: если вёдра ≥2 «?» и текущей зоне нужен один из них — выбор вслепую; промах = П2
  (пятно + порча + смывка).
- «?» + дефицит = главная ловушка поздних уровней (§7, §9).

## 7. Прогрессия уровней
- Число зон: `zones(L) = min(5 + floor((L−1)/10), 8)` → L1–10: 5; L11–20: 6; L21–30: 7; L31+: 8.
- Загрузка уровня: `P(L) = 55 + 5·min(floor((L−1)/10), 4)` порций → 55…75 (держит сессию 30–60с, §10).
  Объём зоны = `P/zones ± 3`, целые.
- Вёдра: по ведру на цвет уровня, 4–6. **Правило дефицита** (на каждое ведро): сумма порций
  ведра = нужде своего цвета на уровне **ровно** (дефицитное) или **+10..15%** (буферное).
  Дефицитных вёдер: L1–5 — 0–1, L6+ — 1–2. «?»-вёдра: с L5, 1–2 на уровень.
- Модификаторы — по диапазонам уровней; каждые 10 уровней добавляют один слой. Все три —
  правила маршрутизации, новых глаголов не создают:

| Диапазон | Модификатор | Механика |
|---|---|---|
| L11+ | Замок на ведре | 1–2 ведра закрыты до заполнения первой зоны; вскрываются автоматически при смене подсветки |
| L21+ | Канал-маршрут | жёлоб к зоне идёт над зоной-мостом: пока мост не заполнен, канал закрыт, целевая зона не подсвечивается (тапы не принимаются, порции не горят) |
| L31+ | Двойная зона | зона из двух контуров с общим счётчиком (12 = 7+5); капля летит в текущий незаполненный контур; перелив считается по общему счётчику |

## 8. Звёзды
| ★ | Условие |
|---|---|
| 3 | завершено, 0 пятен, смывка не использована |
| 2 | завершено, пятен ≤2 |
| 1 | завершено (пятен сколько угодно) |

Порча зоны = 1 пятно + смывка → гарантированно ≤2★.

## 9. Экономика порций: разбор уровня L8 (5 зон, 4 вёдра)
Зоны (порядок = порядок подсветки); нужда 55 = P(8):

| # | Свотч | Объём |
|---|---|---|
| 1 | синий | 14 |
| 2 | оранжевый | 14 |
| 3 | синий | 8 |
| 4 | зелёный | 10 |
| 5 | красный | 9 |

Вёдра:

| Ведро | Цвет | Порций | Нужда | Запас | Роль |
|---|---|---|---|---|---|
| A | синий | 22 | 22 | 0 | дефицитное |
| B | **«?»** → оранжевый | 16 | 14 | +2 (+14%) | буфер |
| C | **«?»** → зелёный | 11 | 10 | +1 (+10%) | буфер |
| D | красный | 9 | 9 | 0 | дефицитное |

**Ловушка уровня (двойная):**
1. Информационная: зона 2 (оранжевый) — первый форк «?»: B и C неотличимы, 50/50. Тап по C
   → зелёный в оранжевую зону = П2: пятно, зона испорчена, C 11→10 (зелёный становится
   дефицитным ровно 10/10).
2. Экономическая: A и D без запаса — любой сгоревший синий/красный тап делает уровень
   непроходимым (провал по §4).

**Разбор:** чисто: A×14 → B×14 → A×8 → C×10 → D×9 = **55 тапов** → T = 55/1.5…2 тапа/с + 8с
= **36–45с** (§10). Через ловушку: 1 тап C + 3 тапа белым + перезалив B×14 = **59 тапов**
→ **39–49с**, 2★ (1 пятно, смывка использована). Второй лишний пролив → C<10 → предикат
провала (§11) → оффер отката.

## 10. Сессия (D12)
- **30–60 сек на уровень.** Формула: `T ≈ P/τ + C`, где τ = 1.5–2 тапа/с (капля 0.4с, ввод
  не блокируется), C = 5–8с (смены зон, финишный ревел). P = 55…75 → T = **36–58с**.
- Ошибки остаются в коридоре: разбор L8 с ловушкой — 59 тапов → ≤49с (§9).
- R1–R5: pass (жидкость = 2D heightfield в шейдере, R5 ok). Яндекс Игры / Poki / CrazyGames:
  однопоточный WebGL, вес минимальный.

## 11. Монетизация — только rewarded, фальсифицируемо (D12)
Каждый показ — событие `reward_offer_shown{product, trigger, level}`; триггеры — измеримые
предикаты внутри уровня, капы жёсткие:

| Продукт | Эффект | Триггер показа (измеримый) | Кап |
|---|---|---|---|
| Откат последнего тапа | порция возвращается в ведро; пятно, порча и счётчик зоны откачены | первый пролив уровня (П1 или П2); повторно — каждый следующий пролив | ≤2/уровень |
| Подсказка «следующее верное ведро» | подсветка верного ведра для текущей зоны | нет тапов ≥5с при активной подсвеченной зоне ИЛИ ≥2 «?»-вёдра в момент смены подсветки | ≤3/уровень |
| Extra-смывка | +1 белое ведро (3 порции) | текущая зона испорчена И своё белое ведро пусто | ≤1/уровень |
| Перед провалом | один из офферов выше перед экраном FAIL | предикат провала истинен: сумма цветных порций < суммы остаточных нужд (показываем откат, если проливов >0; иначе extra-смывку, если блокирует испорченная зона) | 1 экран |

Фальсификация: триггер без конверсии показ→просмотр <3% на 1000 показов — точку убираем.

## 12. Векторы напряжения (B6)
Все векторы — одного медленного контура; **таймера и дедлайнов НЕТ**:

| Вектор | Тип давления | Совместимость с релаксом |
|---|---|---|
| порядок зон (подсветка, каналы) | планирование | темп задаёт игрок |
| перелив, экономия порций | ресурс (бережливость) | время не давит |
| «?»-вёдра | информационный риск | раскрывается в темпе игрока |
| дефицитные вёдра | подсчёт в голове | арифметика без спешки |

Конфликтующих векторов нет: ни один не требует скорости или реакции (B6 pass).

## 13. Управление и ограничения (B7)
- Только одиночные тапы. **Force-touch, долгие нажатия, свайпы, жесты вторым пальцем
  не используются и не заложены в ядро.**
- Финишный «до/после»-ревел канвы (пустая → собранная картина) — стандартный финальный
  момент жанра; инновацией не считается и нигде не называется.

## 14. CPI-крючок
«Успей залить и не пролей!» — струя, капля и перелив читаются за 1 секунду без слов.

## v3.1 — Три жизни (2026-08-27, директива пользователя)
- **3 сердца** на уровень. Потеря сердца: перелив-событие — выбрано ведро больше
  нужды текущей зоны, излишек пролился (−1 сердце за СОБЫТИЕ пролива, не за порцию).
- Чужой цвет: зона ОТКАЗЫВАЕТСЯ принимать (без штрафа — реализм, нет случайных порч).
- 0 сердец = немедленный провал. Сердца не восстанавливаются внутри уровня.
- Бейдж зоны = свотч цвета + число требуемых порций. Идеальный уровень: суммы вёдер
  = суммы нужд зон (ноль переливов) — такие числа и Leveldesign собирает.
- «1/5» на прогрессе = заполнено зон из 5.

## v4 — КРАН: интерактив и ключевые анимации (З8: механика читается из формы)
Модель-основа: бак крана = общее горлышко (цвет k, объём t). Форма крана кодирует
состояние модели — игрок читает её без правил.

### Анатомия (5 частей = 5 смысловых узлов)
1. Кронштейн на стене + рычаг-рукав — статика, фон.
2. **Стеклянный бак-окошко** в голове крана — главный инфоэлемент: видно ЦВЕТ (k)
   и УРОВЕНЬ краски (t) — живое состояние модели v4.
3. Вентиль-барашек — интерактив поворота (заряд/литьё).
4. Поворотное колено-носик — доворачивается к текущей зоне (цель).
5. Впуск с присоской снизу/сбоку — стык шланга от ведра (источник).

### Цикл взаимодействий
- ЗАРЯДКА (A1, тап по ведру): шланг-присоска перелетает к ведру (0.2с) → поток
  краски вверх по шлангу (0.5с) → окошко бака заполняется снизу до уровня ведра →
  вентиль проворачивается со щелчком (0.25с) → ГОТОВ.
- ЛИТЬЁ (A2, тап по подсвеченной зоне): носик доворачивается к зоне (0.2с) →
  вентиль крутится → струя → УРОВЕНЬ ОКНА БАКА ПАДАЕТ синхронно с ростом уровня
  зоны (два жидкостных уровня зеркалят друг друга — замена «цифр под цифрой», З6) →
  зона закрыта: штамп «10/10» + контур застывает.
- СМЕНА ЦВЕТА (промывка): заряд чужого ведра при непустом баке → ПРОБКА СНИЗУ
  мигает красным + кран кренится назад, остаток вытекает в ведро-отстойник (−♥),
  пробка закрывается, новая заливка. Штраф телеграфируется ДО подтверждения тапа.
- НЕДОЛИВ: вентиль перекрыт, носик уходит, зона остаётся с частичным уровнем и
  пунктиром «ещё N» — состояние видно.
- IDLE: редкая капля из носика (раз в 2с) — живость без информационного шума.

### Почему это З8
Окошко = состояние, вентиль = действие, носик = цель, присоска = источник.
Форма крана = визуальная инструкция модели. Реализация в Godot — твины спрайтов +
шейдер уровня жидкости; дёшево, а перелив позже поднимается тем же heightfield-шейдером.

## v3.2 — СЛОЖНЫЙ УРОВЕНЬ L25 «Цех» (матмодель + мокапы)
Модель уровня: задача на РАЗБИЕНИЕ. Для каждого цвета: Σ порций вёдер = Σ нужд зон,
и существует ровно одно чистое разложение. Чужой цвет не принимается. Сердца ×3:
каждое событие перелива (выбрал ведро больше/не для той зоны) = −1 ♥.

### Числа L25 (проверено руками)
Зоны: Z1 синяя 6 · Z2 оранжевая 7 · Z3 синяя 3 · Z4 красная 8 · Z5 оранжевая 9.
Вёдра: синее 6 · синее 3 · красное 8 · оранжевое 7 · оранжевое «?» (=9, скрыто).
По цветам: синий 6+3 = 6+3 (Z1+Z3) ✓; красный 8 = 8 (Z4) ✓; оранжевый 7+9 = 7+9 (Z2+Z5) ✓.
Всё сходится ВЫШИЙ КОРЫТ — решение с 0 потерь существует и ЕДИНСТВЕННО:
  Синие: 6→Z1, 3→Z3 (6 в Z3 = перелив 3, −♥; 3 в Z1 = недолив).
  Оранжевые: 7→Z2, «?»→Z5. КЛЮЧЕВАЯ ДЕДУКЦИЯ: объём «?» не показан, но
  Σоранжевых зон = 16, видимое ведро = 7 ⇒ «?» = 9 — скрытое число ВЫВОДИТСЯ
  арифметикой (З3: скрытое = ставка, награда за думание, не рулетка).
Ловушки (по −♥ за ошибку):
  1. Синее 6 → Z3 (нужно 3): перелив 3.
  2. Оранжевое 7 → Z5 (нужно 9): недолив 2, придётся тратить «?».
  3. Оранжевое «?» 9 → Z2 (нужно 7): перелив 2.
  4. Открыть «?» раньше времени — не ошибка, но план без резерва хрупок.

## v6 — БЕЗ ПОСРЕДНИКОВ: ВЁДРА ЛЬЮТ САМИ; ЗАЛИВКА ОБЛАСТИ ЖИДКОСТЬЮ (2026-08-28)
Директива: «кран с шлангом не нужен. где эргономика? лишний предмет. можно самими
вёдрами лить» + «Paint Loop был без вокселей — заливкой области, пусть и с
воксельными границами, но внутри фулл заливка». Разбор по З12: кран+шланг =
посредник без состояния = декорация → УДАЛЕНЫ (повтор урока «шланг
неэргономичен»; зафиксировано в hot memory).
- **Кор-действие:** тап по ведру → ведро подпрыгивает к канве и НАКЛОНЯЕТСЯ над
  подсвеченной зоной, ДУГА жидкой краски льётся сверху прямо в зону (референс:
  песок в Sand Loop льётся дугой вверх в картину).
- **Заливка области ЖИДКОСТЬЮ (не воксель-порции):** зона = область попугая;
  тап = одна порция-доза; внутри зоны растёт ЖИДКИЙ УРОВЕНЬ с горизонтальной
  поверхностью, глянцем и бликом (heightfield). Пиксельная сетка остаётся как
  тонкие швы/фаски границ, но внутри области — сплошная гладкая заливка.
  Бейдж зоны «N/M» = мелкий лейбл; главный сигнал = сам уровень жидкости (З6).
- Порции вёдрах: счётчик/уровень на ведре; пустое ведро остаётся бутылкой.
- Чужой цвет = ОТКАЗ: струя отскакивает от зоны каплями в стороны, серый ❌
  над зоной, зона дрожит — без −♥ (v3.1). Перелив (лишняя доза / полная зона):
  волна через край зоны + брызги + лужа на раме + −♥ (тряска пилюли сердец).
- Словарь анимаций: прицел (палец+рябь на ведре, пунктирная дуга ведро→зона,
  зона подсвечена) → литьё (наклон ведра, дуга, уровень растёт, капли) →
  успех зоны (уровень дошёл до края, глянец вспыхивает, ✓-бейдж, лучи) →
  перелив (волна через край, −♥) → отказ (отскок, ❌) → победа (LEVEL
  COMPLETE, конфетти, вёдра пусты, 2♥).
- Уровень-эталон: числа L25-v2 сохраняются (6/6/6/3/3, Σ=24 доз), но дозы
  заполняют ЖИДКИЙ уровень зоны (M доз = полный), а не кубы.
- Сториборд: серия pl6_* (эталон-карта tools/paintloop_map.py — без крана).
  v5-сториборд pl1–pl4 (кран) — АРХИВ, отвергнут по З12.

## v3.2 — ПРОГРЕССИЯ ПО З-РАСКЛАДКЕ (2026-08-28, директива)
Эталон Voodoo (509 уровней, L40–L3500): сетка и набор механик НЕИЗМЕННЫ с L1;
сложность = комбинаторика раскладки; новые механики — редкие точечные события
(L12 гейты, L90 квоты). Прогрессия Paint Loop:
- L1–10: все механики доступны сразу (перелив, чужой цвет, смывка, «?»).
  Объёмы совпадают почти точно → обучение без стресса.
- L11–40: объёмы расходятся (дефицит/излишек), «?»-вёдра чаще,
  зоны требуют планирования порядка.

  (два вёдра с разницей в 1 порцию).
- Стены каждые ~40 уровней: уровень-головоломка ×5–7 времени
  (монетизация: подсказка/откат).
