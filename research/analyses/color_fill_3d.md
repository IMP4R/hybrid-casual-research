# Color Fill 3D (Good Job Games) — разбор хита-референса до концепт-документа

База: `research/screens/color_fill_3d/DOSSIER.md` (App Store 4.6 / 381 563 оценок, AI GAMES FZ LLC; Google Play `com.gjg.colorfill3d`; CrazyGames-порт) + 14 скринов, просмотренных глазами: `play_shots/shot1–6` (уровни 4, 5, 7, 10, 11, 12), `itunes_shots/shot1–6`, `yt_thumbs/5QTuNqxQA0I`, `crazygames_cover.jpg`. Скрины представляют две сборки: play-версия (Level N + чип алмазов) и store-версия (сегментированная полоса с номерами уровней) — расхождение зафиксировано в §3.
Один лист вывода: **path-fill — отдельный (пятый) скелет, отсутствующий в матрице `combos_hypotheses.md` S1–S4**; полный разбор — §7.1.

## 1. Матмодель

**Состояние.**
- Сетка клеток; каждая клетка ∈ {стена контура, свободна, закрашена, врата-замок}. Контур поля = пиксель-арт силуэт (рыба, лицо, щит) — сама фигура уровня.
- Игрок: одна клетка + направление; движение непрерывное с постоянной скоростью, темп задаёт палец.
- Препятствия двух классов (по рендеру): (а) сеточные блоки из кубов — компактные группы 1×3, 3×3, 2×5, часть = предзаливка картины; (б) гладкие бесшовные плиты вне сетки рельефа (розовый квадрат L11, серая плита L4) — класс подвижных препятствий. Поведение подвижных (патруль/движение навстречу) **[inference]** — в статике не верифицируется.
- Врата-замки с иконкой замка в стене/перегородке (L10, L11); условие открытия **[inference: все клетки доступной зоны закрашены]**.
- Алмазы: 3–6 позиций на поле, флаг собранности.
- Счётчик закрашено/всего свободных → полоса прогресса.

**Действия.** Единственное: `steer(направление)`. Каждый вход в клетку переводит её свободна→закрашена. Повторный вход в закрашенную разрешён **[inference: пути на кадрах свободно самопересекаются, шлейф не блокирует]**.

**Ограничения.** Стены контура; подвижные препятствия (контакт = провал **[inference]**); врата до условия. Краска не кончается; клеточного ресурса нет; таймера нет.

**Победа:** все свободные клетки закрашены (полоса 100%). **Провал:** контакт с подвижным препятствием → рестарт уровня **[inference]**.

**Горлышко (честно, по З0/З2): отсутствует.** Целевая функция = Σ[клетка закрашена] — аддитивна по клеткам; порядок закраски не влияет на результат; дефицита нет; решения не взаимодействуют. По духу теоремы пустоты: сложность матмодели ≈ 0. Всё напряжение вынесено из математики в: (а) полноту покрытия (внимание), (б) обход подвижных препятствий (реакция/микро-план), (в) топологию поля (карманы в один вход, перешейки). Это игра про flow и сенсорику, не про решение.

**Функция сложности [inference].** Рост через: размер контура (~80→150 клеток), изрезанность контура (периметр/площадь → больше карманов), число и агрессию подвижных плит, число врат (дробление поля на зоны → граф достижимости), многоцветные/многоэтапные уровни. Рост **линейный по площади, не комбинаторный** → потолок глубины низкий; после ~L50 новизну держит только конвейер картинок.

**Числа сессии [inference]:** 20–60 с/уровень; ~100–130 закрашиваемых клеток; скорость куба 8–12 клеток/с.

## 2. Кор-глагол + правила

Кор-глагол ровно один: **`steer_cube`** — ведёшь куб пальцем (свайп/удержание), куб непрерывно едет и красит клетки. Других постоянных глаголов нет:

| Не глагол | Почему |
|---|---|
| тап по клетке | клетки не выбираются — красятся только проездом |
| выбор цвета | цвет заливки уровня задан, игрок не выбирает |
| откат / ластик | отсутствует; закрашенное не убирается |
| сбор алмаза | побочный эффект проезда |
| открытие замка | авто-условие, не действие игрока |
| бустеры | в кадрах ядра не видны **[inference]** |

Правила ядра:
1. **Краска = состояние клетки.** Необратима по цвету; повторный проезд валиден, но ничего не меняет — единственная цена ошибки маршрута, потерянное время.
2. **Препятствия.** Сеточные цветные блоки = предзаливка картины (не мешают движению **[inference]**); гладкие плиты = класс опасных (контакт = провал **[inference]**).
3. **Врата-замки** — единственный «порядковый» элемент скелета (зародыш порядка-блокировок внутри path-fill): зона за вратами вскрывается после закрытия текущей **[inference]**.
4. **Алмазы** лежат на «неудобных» ветках (углы, дальние карманы) → микро-развилка «крюк ради алмаза против короткого пути».
5. **Многоцветность уровня** (L7 оранжевый+голубой; L12 красный+циан; itunes: розовое лицо + фиолетовый фон): уровень = предзаливка фигур одного цвета + фон, который игрок красит своим цветом; финал = собранная многоцветная картинка **[inference: альтернатива — этапы со сменой цвета между зонами]**.

## 3. UI/интерактив

- Верх: «Level N» по центру; чип «алмаз + число» справа; полоса прогресса уровня во всю ширину.
- Полоса, две версии: **store** — сегментирована, на границах сегментов номера уровней («5 ▬▬ ▬▬░ 6»); заполнение текущего сегмента = доля закраски. **play** — номера убраны, в середине полосы алмаз-«веха» **[inference: награда на середине]**. Эволюция к «нулю слов».
- **Закраска поднимает клетку в 3D-объём**: прогресс виден рельефом поля, без единого числа — канон З6.
- **Градиент свежести**: у головы куба клетки почти белые, стареют к полному цвету — телеметрия последних секунд пути.
- **Контур-силуэт = обложка и туториал одновременно**: цель считывается из формы до первого движения (З8).
- **Спавн-коридор** (снизу; на L11 сверху) телеграфирует точку входа и первые метры.
- Замок-иконка на месте врат; частицы крошки на событиях (itunes shot4) — обратная связь без текста.
- Провал/финал в статике не попали **[inference: рестарт без меню; финальный ревел собранной картинки — жанровый стандарт, не инновация (З10)]**.
- Управление: свайп/удержание, без кнопок, без force-touch.

## 4. Прогрессия / монетизация

- Уровни бесконечные («infinite number of exciting levels» — стор); контент = конвейер контуров-картинок + перебор модификаторов.
- Кривая **[inference]**: площадь/изрезанность → +подвижные плиты (видны с L4) → +врата (L10–11) → многоцветные и многоэтапные конфигурации. Новых глаголов нет вообще.
- Алмазы: 3–6 на поле; баланс чипа между записями одной пачки скринов не монотонен (52, 129, 133, 202, 170, 156; в store-версии 5→0) → траты/начисления вне ядра **[inference: скины куба/тем в шопе]**.
- Монетизация в кадрах не видна **[inference, стандарт Good Job Games/AI GAMES]**: interstitial между уровнями, IAP no-ads, rewarded за косметику. Ключевой структурный факт: **в ядре нет боли, которую можно лечить бустером** — провал дешёвый (рестарт), дефицита нет, застревать негде. Вся монетизация висит на рекламе и косметике, а не на геймплейных болях — главное отличие от S1/S2, где rewarded лечит реальные застревания.

## 6. Слабости

1. **Нулевое горлышко (З2/З3).** Аддитивная цель без дефицита: матмодель не создаёт напряжения, вся сложность = внимательность + обход. Удержание держит сенсорика, не глубина.
2. **Нет необратимых ставок (З1/З4).** Ошибка маршрута стоит секунды; ни одно решение не «стоит» ресурса → нет момента «надо было иначе» после факта.
3. **Провал-рестарт (З5).** Контакт с плитой обнуляет уровень; состояние не развивается от ошибки. Противоречит собственному позиционированию стора («calming», «relaxing») и режет flow.
4. **Потолок глубины.** Комбинаторика не растёт с номером уровня — только длина маршрута; единственный источник новизны = конвейер картинок. Скелет тривиально клонируется (что рынок и подтверждает).
5. **Монетизация не связана с ядром.** Нет дефицита → нет боли → нет честных бустеров; экономика = реклама + косметика, ARPPU-потенциал ниже S1/S2.
6. **Алмазы в вакууме.** Назначение валюты не читается из ядра **[inference: скины]** — слабая связка «усилие → награда».

## 7. КОРРЕЛЯЦИИ

### 7.1 Скелет: «path-fill» — третий тип матрицы (S1/S2/S5)

В `combos_hypotheses.md` v1 скелеты S1–S4; **path-fill в матрице отсутствует, хотя хит с 4.6/381k его реализует** — фиксирую как S5 «заливка маршрутом»: куб красит сетку, путь = заливка. Сложность не порядковая (S2) и не объёмная (S1) — она **маршрутная** (геометрическое покрытие одним агентом).

| Ось | S1 Pixel Flow (заливковые) | S2 Hexa Away (порядок-блокировки) | S5 Color Fill 3D (path-fill) |
|---|---|---|---|
| Носитель сложности | порядок подачи цветов + объёмы зон | топологический порядок выпуска (кто кого блокирует) | геометрия покрытия: как одним маршрутом войти во все карманы и выйти |
| Ресурс/горлышко | краска питателей (кончается — З2/З3) | слот выпуска/путь (занят) | **нет**; маршрут-время — слабый суррогат |
| Провал | исчерпание/перелив — архитектурный | тупик «некого выпускать» — архитектурный | контакт с плитой — **тактильный**, рестарт |
| Необратимость | жёсткая (порция сгорела) | жёсткая (порядок исполнен) | мягкая: клетку не испортишь, можно проехать снова |
| Ловушка | дефицит + «?»-вёдра | цикл блокировок | карман в один вход + плита на перешейке |
| Функция сложности | комбинаторная (разбиение сумм) | топологическая (частичный порядок) | метрическая (длина ~ площадь) + динамическая (плиты); растёт линейно |
| Потолок глубины | высокий | высокий | низкий |
| Скрытая информация | ?-вёдра, скрытые объёмы (З4) | содержимое очередей | почти ноль |
| Что продаёт | решение под щадящим давлением | разгадку порядка | satisfying-покрытие + картинку |

**Ключевое различение, ради которого S5 = отдельный тип:** у S1/S2 провал архитектурный — модель сама говорит «план был неверен, переиграй»; у S5 провал тактильный — «не увернулся». Глубина S5 не растёт с уровнем в принципе — растёт только длина. Поэтому S5-игры продают не решение, а след: перманентный видимый маршрут, рельеф, контур-картинку, и вход с нулевым фрикционом (правил нет вообще — CPI читается без слов).

Зародыши скрещивания уже внутри референса: врата-замки = S2-порядок внутри S5; предзаливка фигур = S1-канва внутри S5. Свободные связки-кандидаты: **S5×S1** (конечная краска на маршрут: покрой поле данным объёмом — привносит настоящее горлышко), **S5×S2** (врата-порядок на несколько зон с зависимостями), **S5×S3** (плиты с окнами тайминга) **[inference: ниша свободна по доступным досье, требует проверки `fetch_game.py`]**.

### 7.2 Горлышко
Отсутствует (§1). Суррогаты S5: (а) полнота 100% клеток, (б) живучесть, (в) длина маршрута — ни один не заставляет решения конкурировать. Урок для матрицы: в S5-гибриде горлышко привносится только извне скелета (буфер краски, лимит разворотов, счётчик шагов), иначе уровень = «закрась всё аккуратно».

### 7.3 Обратная связь
Каждое действие окрашивает клетку немедленно и перманентно, по трём каналам: цвет (закрашено/нет), высота (куб поднимается), светлота (свежесть шлейфа). Прогресс дублирован полосой. Отличие от S1: там след = закрашенная зона; здесь след = **весь маршрут игрока** — история пути становится контентом финальной картинки. Это главный переносимый актив скелета.

### 7.4 Паттерны UI
- Полоса с номерами уровней на границах сегментов (store) — З6 в чистом виде: заполнение = доля закраски, числа = только границы; новая версия убрала числа и добавила веху-алмаз — дрейф к «нулю слов».
- Чип валюты без кнопки шопа на игровом экране **[inference: шоп в один тап от финала]**.
- Контур-силуэт = обложка уровня и туториал одновременно (З8).
- Спавн-коридор = телеграф входа; узкие перешейки = телеграф риска: места встречи с плитами читаются геометрией, без маркеров.
- Замок-иконка на месте врат; частицы на событиях — статус без текста.

### 7.5 Скрытая информация
Почти нулевая: поле, блоки, врата, алмазы видны со старта. Скрыты только траектории подвижных плит (предсказание = навык) и содержимое за вратами. По З4 — слабость: нет ставок, меняющих план до действия. Перенос из S1: «?»-блоки/«?»-врата, раскрывающиеся проездом.

### 7.6 Подача ресурса
Ресурса нет — зато есть порционность **пространством**: врата дробят поле на зоны, зоны вскрываются по мере прохода; игрок коммитит маршрут до вскрытия следующей зоны. Это «буфер пространством» — второй (после ленты времени у S1 и доков у Block Jam) механизм З-БУФЕР: не очередь во времени, а глубина в 2D-топологии. Алмазы на «неудобных» ветках = дозированная мотивация крюков, единственный регулярный выбор внутри уровня.

### 7.7 Итог для матрицы корреляций
1. Добавить S5 «path-fill» пятым скелетом: носитель — геометрия покрытия; провал — тактильный; горлышко — ноль; потолок глубины — низкий.
2. S5 — донор сенсорных активов (перманентный след, рельефный прогресс, контур-картинка) для любых S1/S2/S4-игр: слой обратной связи, а не конкурент по глубине.
3. Дефект S5 лечится только кроссовером: S5×S1 (конечная краска) и S5×S2 (врата-порядок) — оба сохраняют нулевую планку входа и CPI-читаемость, добавляя горлышко, которого в чистом S5 нет.

| Нейтраль сцены (store-версия) | графитово-синий пол с сеткой на полтона темнее; краска даёт максимум контраста кадра | I1–I6 |
| UI-хром | белые/светло-серые капсулы, тёмный текст (игра) / чёрные контуры (store) | все |
| Константа | магента-алмаз с белым блеском — единственный цвет, не меняющийся между уровнями и версиями | все |

Правило читается из кадров: **насыщенность зарезервирована за краской** — фон всегда тише краски минимум на тон; paint-цвет = самый хроматический объект сцены. Валюта (магента) выбита из красочной шестёрки сознательно: собранный алмаз отличим от любой краски уровня.

### 8.2 Форма-язык

- **Воксель-маршмеллоу.** Каждая клетка = отдельный скруглённый куб с большим радиусом рёбер (порядка 15–20% ребра), 2.5D-аксонометрия сверху (~20°). Закрашенное поле физически выпуклое — форма = состояние.
- **Пиксель-силуэт, сглаженный вокселем.** Контур поля ступенчатый с шагом в 1 клетку (рыба, лицо, щит), но каждая ступень мягкая; рамка поля — скруглённый прямоугольник, коридоры — узкие каналы той же стены (P1, P3, I5).
- **Два семейства поверхностей = два поведения.** (а) Клеточные кубы с видимой сеткой граней — краска и предзаливка; (б) гладкие бесшовные скруглённые тела без членения на клетки — опасные плиты (розовый блок P4, серая плита P3) и «труба»-путь на обложке CG. Разные поверхности = разные правила, читается без текста (З8).
- **Радиус — везде.** Капсулы UI, линза-узел полосы, скругления стен, буквы логотипа: в CG логотип «COLOR FILL 3D» — экструдированные воксель-буквы (жёлтые грани/оранжевый бок, розовые грани/фиолетовый бок), форма-язык продукта повторён в логотипе.
- Алмаз — плоский low-poly кристалл с двутоном (светлый верх, насыщенный низ).

### 8.3 Шейдинг

- **Матовый, без спекуляра, ноль текстур.** Материал = чистый цвет + бевел; «материальности» добиваются геометрией, не картой.
- **Три тона на куб:** верхняя грань светлейшая, фронт средняя, бок темнейшая; мягкая контактная тень (AO) под поднятыми кубами и вдоль стен — высота читается тенью (P1, P6, CG).
- **Градиент свежести:** свежая клетка выбелена к белому (~50–70%), насыщенность догоняет цвет краски назад по пути (P4, P6, I1, I5, I6) — временной шейдинг, запечённый в уровень.
- **Play vs store:** play — пол осветлённый тинт hue рамки (светлая сцена); store — графитовый пол (тёмная сцена). Краска одинакова хроматична в обоих: сцена меняет светлоту, краска — никогда.
- Серая виньетка/градиент фона — только на маркетинговом кадре CG; в геймплейных кадрах фон белый, без атмосферы.

### 8.4 Конструкция UI

- **Play-версия, ровно 3 элемента над полем:** «Level N» по центру (скруглённый шрифт, тёмно-серый); чип валюты справа (белая полупрозрачная капсула: магента-алмаз + чёрное число); полоса прогресса во всю ширину — серый трек из двух капсул с ромбовидной линзой-узлом в середине, заливка слева. Ни одной кнопки: нет паузы, настроек, шопа (P1–P6).
- **Store-версия:** полоса из капсульных сегментов с чёрной обводкой, номера уровней на внешних концах («5 … 6»); заполнение текущего сегмента = доля закраски; **цвет заливки полосы = цвет краски уровня** (циан I6, зелёный I3, розовый I4, оранжевый I2/I5; I1 — исключение: оранжевая обводка при фиолетовом шлейфе).
- **Пустой баланс = контурная окружность вместо «0»** рядом с алмазом (I5, I6) — ноль рисуется фигурой, не цифрой.
- Замок — серая пластина с дужкой и замочной скважиной, встроенная в стену коридора в общем мягком стиле (P4, P6).
- Плотность: игровое поле занимает ~70–80% высоты кадра, инфо-полоса ≤ 15% — UI подчинён полю.

### 8.5 VFX-паттерны

- **Частицы = миниатюры клеток:** разлетающиеся кубики цвета краски с гравитацией (россыпь синих мини-кубов I2; жёлтая крошка вокруг блока I4) — даже эффекты держат воксель-форму, никаких искр/глоу.
- **Крест-блёстка на алмазах** — белый четырёхлучевой пульс; единственный sparkle-элемент в кадрах.
- **Градиент свежести** (§8.3) работает как временной VFX: след сам показывает «что произошло только что».
- **Альфа-затухание следа у кромки:** над спавн-коридором свежая краска растворяется градиентом в прозрачность (I4) — вход куба телеграфируется без стрелок.
- Тени статичные и мягкие; динамический свет, скриншейк, вспышки в статике не зафиксированы — не утверждаю.

**Сводка стиля:** «конфетный воксель» — скульптурная форма без текстур, насыщенность как носитель смысла (краска > фон > UI), два семейства поверхностей для двух классов правил, VFX, выращенные из той же формы-языка. Всё в кадре обслуживает одно: закрашенная клетка должна читаться как событие за долю секунды — что и есть визуальный аналог нулевого фрикциона входа из §7.
