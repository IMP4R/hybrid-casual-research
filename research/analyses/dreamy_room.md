# Dreamy Room (ABI Global) — разбор референса до матмодели

База доказательств: DOSSIER.md (стор-описание, хронометраж глав YT), 15 скринов
(`play_shots/` 1–6, `itunes_shots/` 1–6, `yt_thumbs/` — L1–10 коллаж, L787, Weekly Challenge).
Внешний поиск при написании был недоступен; всё, что не читается со скринов/описания,
помечено **[inference]**. Ось анализа: законы З0–З12 (`ontology/design_laws.md`).

**Классификация одним абзацем.** Dreamy Room — не «головоломка без провала», а задача
зрительной ИДЕНТИФИКАЦИИ (предмет → слот) с порционной подачей предметов из коробок.
Решения не соревнуются ни за какой ресурс (З2 = 0), ошибок нет (З5 = 0), таймера нет —
и это не дефект, а смена класса скелета: **«process-ASMR»**, где сложность = нагрузка на
восприятие и семантику, а не на принятие решений. $7M (по условию задачи) куплены
заполнением (completion-петля), историей через предметы и контрактным отсутствием наказания.

## 1. Матмодель

### Состояние
| Сущность | Содержимое |
|---|---|
| `A` — слоты (якоря) | {позиция в изометрии, слой z, **уникальный** требуемый предмет `id*`, зона: пол/стена/этаж-2/за-перегородкой, хост-зависимость: активен только после установки предмета-хоста} **[inference: хост-зависимость]** |
| `I` — предметы | биекция к `A` (у каждого ровно один слот); спрайт, размер (мелкий/средний/крупный), семантический тег |
| `B` — коробки | разбиение `I` на порции `b1..bk`; порядок открытия фиксирован дизайном **[inference: порядок фиксирован; на скринах 1 открытая + 2–3 закрытые коробки: play2, play6]** |
| `live` | предметы текущей порции, висящие в воздухе с покачиванием+свечением (на скринах одновременно live 1–3 предмета: play1, play5, play6 → буфер маленький) |
| `held` | предмет в пальце: 0 или 1 **[inference: drag-модель; альтернатива «тап по слоту» не подтверждается и не опровергается скринами]** |
| `progress` | \|заполнено\| / \|A\| — без цифр, показывается самой комнатой |

### Действия
| Действие | Эффект |
|---|---|
| `open_box(b)` | коробка открывается, световой столб вверх, порция предметов получает `live` |
| `drag(held)` | перенос предмета по сцене |
| `drop(held)` | если `dist(held, slot(held)) < r` → **snap**: предмет встаёт, пыль+скейл-отскок, ASMR-звук, `progress+1`; иначе → предмет возвращается в `live`-hover. **Штрафа нет, ход не сгорает.** **[inference: strict snap только в свой слот, чужой не принимает]** |
| `tap_decor(объект)` | микро-анимация/звук (блики-искры на скринах: play1 — доска меню и фонарь; play2 — магниты на холодильнике). На completion не влияет **[inference]** |
| `camera(pan, zoom)` | есть на крупных сценах (L787 снят зум-аутом: yt_sXMEF83yfAc) |

### Ограничения
- Таймера нет, счётчика ходов нет, провала нет (стор: «no timer, no pressure» — DOSSIER).
- Слоты жёсткие: предмет нельзя поставить «примерно сюда» — только в свой якорь.
  Свобода декорирования в ядре отсутствует **[inference]**.
- Завершение уровня: `filled = |A|` (все предметы по местам).

### Горлышко
**Ресурса, за который соревнуются решения, НЕТ (З2 = 0).** Единственная валвость —
скорость идентификации `item → slot`; её ограничивает не игра, а игрок:
поиск взглядом, память о невидимых зонах, семантическая догадка. Клапан темпа —
порционность коробок: новое знание (что в коробке) выдаётся только после освоения предыдущего.

### Победа/провал
Победа — единственный исход: комната собрана → ревел-пан, персонаж, «фотография».
Провал невозможен. Ошибка = no-op (предмет вернулся), состояние не изменилось (З5 = 0).

### Функция сложности
Время до победы: `T ≈ Σ c_i + M·t_snap + t_поиска_паузы`, где стоимость идентификации
предмета `i`: `c_i = f(видимость слота, #похожих слотов, размер предмета, семантическая ясность, этаж)`.
Все множители монотонные, между решениями нет взаимодействий → сложность растёт ОБЪЁМОМ
и ОККЛЮЗИЕЙ, а не комбинаторикой. Числа **[inference]**: L1–10 (yt-хронометраж глав
0:50–3:00) — 1 комната, ~15–30 предметов, 30–90 c; середина (play3 — лофт 2 этажа) —
40–80 предметов, 1–3 мин; поздние (L787 — здание) — 100+ предметов, 5–15 мин, работа камерой.
Вектор роста: зоны (этажи) → окклюзия (перегородка play6, мебель-хосты) → гранулярность
(мелочь) → похожесть слотов (4 одинаковых стула). Новых правил за 787 уровней — ноль.

## 2. Кор-глагол + правила

**Ровно один кор-глагол: `drag_item_to_slot`.**

| Не глагол | Почему |
|---|---|
| `open_box` | подача порции (клапан темпа), не решение; аналог «подсветка ведёт» |
| `tap_decor` | игрушка-рефлекс, состояние модели не меняет |
| `camera` | навигация, а не действие над моделью |
| вращение предмета, инвентарь-меню, покупка/удаление/откат | отсутствуют **[inference: на скринах нет UI инвентаря и режимов]** |

Правила (их всего три, и все — про ЧТЕНИЕ, а не про выбор):
1. **Биекция.** У предмета ровно одно место; чужой слот не принимает.
2. **Порция.** Предметы выдаются коробками; открыть следующую можно до/после — темп свой.
3. **Без наказания.** Промах ничего не стоит. Контракт: игра никогда не бьёт.

Правило №3 — не отсутствие дизайна, а дизайн: вся «сложность» перенесена из оси
«решение–штраф» в ось «поиск–находка». Это и есть скелет process-ASMR.

## 3. UI/интерактив

- **HUD из трёх элементов** (itunes1–6): кнопка магазина (слева, иконка пакета),
  номер уровня «0089» (центр), звёзды ★181 (справа). В игровом поле кнопок нет вообще —
  единственные интерактивные объекты: коробки, предметы, блики-искры, камера.
- **Каналы внимания:** световой столб из открытой коробки (funnel к источнику действия),
  покачивание + свечение live-предметов, блики на интерактивном декоре.
  Цель (слот) намеренно НЕ подсвечивается — скрытая цель и есть игра (З4).
- **Фидбек каждой расстановки:** snap + пыль + скейл-отскок + мягкий звук; каждые ~3–5 с
  guaranteed микро-награда **[inference: частота от длительности глав]**.
- **Прогресс = сама комната** (З6-эталон): пол/стены/этажи заполняются на глазах,
  счётчиков нет. Финал = ревел-пан + персонаж + «фотография» жизни (жанровый стандарт, З10).
- **Масштаб:** крупная сцена обслуживается зум-аутом и панорамой (L787), HUD не меняется.
- **Ивент-кожа** (yt_tlaf1ENEsNs): иная графика HUD — таймер 03:06, полоса прогресса с
  милями, LV.35, панель бустеров со счётчиками (лампочка 19, лупа 12, «?» 3, компас 15),
  бурст «AMAZING!». Тот же движок сборки, другой контракт (см. §4, §6).

## 4. Прогрессия/монетизация

**Прогрессия.** Линейная лента уровней 1 → 787+ (yt-плейлисты солюшенов) без карты-прокрутки
в HUD — номер уровня вместо карты. Контент-ось двойная:
- **Сцена:** детская → студенческая → первая квартира → семейный дом… (стор «жизнь по годам»,
  DOSSIER; персонажи-маскоты: кролик, кот, капибара, медведь — play2, play6, play5, yt_sXMEF83yfAc).
- **Размер:** комната → лофт (play3) → здание (L787) → тематический мир ивента
  (turtle-pirate: yt_tlaf1ENEsNs). Сложность растёт только геометрией и окклюзией.
- Звёзды ≈ 2/уровень (★181 к L89 **[inference: линейная экстраполяция HUD]**) — soft-currency
  для магазина (кнопка в HUD). Магазин внутри ядра на скринах не раскрыт **[inference:
  ожидаемо декор/темы/бустеры]**.

**Монетизация** **[inference по совокупности: HUD, ивент-панель, жанровые стандарты]**
| Источник | Механика |
|---|---|
| Interstitial | между уровнями; в релакс-ядре это главный AD-объём |
| Rewarded | подсказка «куда этот предмет», пропуск нудной фазы, валюта ивента |
| IAP | отключение рекламы, валюта/бустеры ивента, декор |
| Weekly Challenge | отдельная петля: таймер 03:06, бустеры с расходуемыми счётчиками, мили с наградами, FOMO-дедлайн |

**Ключевая экономическая развилка:** без провала нет точек «спаси меня» → меньше
rewarded-конверсий, чем в fail-based жанрах ($7M против $189M-скелета sort-игр из
paint_loop_concept). ABI компенсирует: (а) объёмом interstitial-показов на длинной
короткой сессии, (б) второй петлёй (ивент), где провал и дедлайн есть и бустеры расходуются.

**CPI-крючок:** коробка → предметы вылетают → satisfying snap; «распаковка чужой жизни» +
уют без слов. Креатив продается движением предмета в слот — тот же глагол, что в игре.

## 5. Сильные стороны по З1–З8

| Закон | Вердикт | Разбор |
|---|---|---|
| З1 необратимые альтернативы | ✗ (осознанно) | Ни одна расстановка не необратима и ничего не стоит. Коммиттится внимание, не ресурс. Для класса process-ASMR это норма, для З0-игры — запрет |
| З2 общее горлышко | ✗ (осознанно) | Ресурса нет; решения не взаимодействуют. Куплена бесконфликтность = релакс |
| З3 конечный ресурс и каскад | ✗ | Ничто не кончается, каскадов нет |
| З4 скрытая информация = ставка | ✓✓ | Сильнейший элемент: содержимое закрытой коробки; слоты за перегородкой/на 2-м этаже; слот появляется после хоста (сначала шкаф — потом рамка обретает место **[inference: хост-цепочки]**); семантическая догадка «куда это кладут в жизни». Скрытое реально меняет порядок действий игрока |
| З5 ошибка = новое состояние | ✗ (осознанно) | Ошибка = no-op. Контракт «никогда не бить» — цена за ASMR |
| З6 прогресс полосой | ✓✓ | Эталон: комната сама = полоса прогресса; ноль «цифр под цифрой»; точные числа не нужны вовсе |
| З7 переносить топологию | ✓ | Переносимо: окклюзионная топология, похожесть слотов, порционная подача, хост-цепочки. Не переносится (декорации): уютный арт, сторителлинг, маскоты |
| З8 интеракции в рендере | ✓ | Световой столб = «здесь источник», покачивание+свечение = «я живой, меня тащи», snap-анимация = «встало навсегда». Форма предметов читается: спрайты с явным «местом в мире» (полка с ячейками, стол с сервировкой) |

Суммарно: **проигрыш по Ярусу 1 (З1–З3) при образцовой Ярус-2 читаемости (З4, З6, З8)** —
и это честная цена выбранного класса скелета.

## 6. Слабости

1. **Нет ядра решений в смысле З0:** решения не взаимодействуют, mastery-потолок ≈ 0.
   Удержание держится на контенте и эмоции, а не на росте навыка → лента уровней обязана
   быть бесконечной.
2. **Себестоимость контента:** 787+ уровней уникальной сцены — asset-тредмилл; жанр
   почти не переиспользует комнаты (сцена = контент). Самая дорогая единица прогресса в
   казуале.
3. **Pixel-hunting:** на поздних уровнях `c_i` растёт гранулярностью мелочи и окклюзией —
   нагрузка превращается из «приятного поиска» в фрустрацию. Индикатор: индустрия
   walkthrough-каналов с солюшенами уровней 787 — спрос на обход поиска существует
   (одновременно это и бесплатный UA-канал).
4. **Моноверб:** глагол один и не эволюционирует; модификаторов уровня (аналог замка/
   канала Paint Loop) нет — только геометрия сцены. Риск пресыщения без обновления правил.
5. **Ивент ломает контракт:** таймер 03:06 + бустеры + FOMO против «no timer, no pressure».
   Два продукта в одном приложении; каннибализация релакс-ядра и риск жалоб аудитории.
6. **Монетизационный потолок:** нет провала → нет save-моментов → rewarded-конверсия ниже,
   чем у fail-based соседей; ставка на interstitial-объём делает доход чувствительным к
   eCPM и медийной политике сторов.

## 7. КОРРЕЛЯЦИИ

### 7.1 Скелет
**«process-ASMR» = сборка по эталону (hidden-object assembly) с порционной подачей.**
Формула: сложность без таймера и провала = нагрузка на ВОСПРИЯТИЕ и СЕМАНТИКУ,
а не на решение. Класс задачи — «matching under occlusion»: биекция предмет→слот,
поиск осложнён невидимостью и похожестью; конфликт и штраф отсутствуют по контракту.
Родня: Unpacking, A Little to the Left, скрытый объект. Для нашей онтологии это второй
базовый класс скелетов рядом с «соревнованием решений» (sort/paint): у него другая ось
сложности (поиск vs выбор), другая экономика (нет save-моментов) и другой контракт
(никогда не наказывать). Проверка на З0-теорему пустоты: да, при отсутствии горлышка
decision-сложность = 0 — теорема работает; Dreamy Room не опровергает её, а живёт в
другой оси. Смешение осей в одном ядре (риветливый поиск + ресурсное решение) —
открытая гипотеза для нашего скелета (см. 7.7).

### 7.2 Горлышко
Горлышко решений отсутствует (З2=0); функциональное горлышко — **скорость идентификации**,
которую игра дозирует клапаном порций. Практический вывод для наших скелетов: если горлышко
решений убрать нельзя (З2), дозировать НАГРУЗКУ можно тем же клапаном — буфером прибытия
(З-БУФЕР), и это работает даже без провала.

### 7.3 Обратная связь
- **Settle-петля** — главная единица удержания: snap + пыль + звук + прирост комнаты
  каждые ~3–5 с; гарантированная микро-награда без единого наказания.
- **Комната = живая полоса прогресса** (З6 в предельной форме): прогресс не показывается —
  он и есть сцена. Прямой перенос в Paint Loop: заполненная канва/комната вместо счётчиков.
- **Ноль наказаний как контракт** — противоположно З5 («ошибка = новое состояние»);
  выбор З5 или no-op-ошибки определяется классом скелета, а не «правильностью».

### 7.4 Паттерны UI
- Световой столб из коробки — funnel к источнику действия (дешёвый телеграф «иди сюда»).
- Live-предметы: покачивание + свечение = «я интерактивен» без слов (З8).
- HUD из 3 элементов; поле без кнопок — все клики уходят в сцену.
- Зум/пан для масштабных сцен при неизменном HUD.
- Бурст «AMAZING!» и мили-полоса — ивент-кожа поверх того же движка.
- Финальный ревел-пан — жанровый стандарт, инновацией не считать (З10).
- Блики-искры на декоре — опциональный слой «игрушек» вне модели (безопасный способ
  добавления интерактивности, не создающий глаголов).

### 7.5 Скрытая информация
Четыре слоя, по нарастанию глубины:
1. **Содержимое закрытой коробки** — что будет дальше (план «сначала коробку A»).
2. **Окклюзия** — слоты за перегородкой/мебелью/на 2-м этаже; раскрывается камерой и установкой.
3. **Хост-зависимость** — слот не существует, пока не стоит хост **[inference]**; порядок
   установки становится планом, а не прихотью.
4. **Семантика** — «куда это кладут в жизни»: пачка подгузников → детская, а не в бар
   (стор как констрейнт-подсказка). Уникально для жанра: нарратив снижает `c_i`,
   т.е. история здесь — механический элемент, а не декорация.

### 7.6 Подача ресурса
Коробки = **З-БУФЕР в чистом виде**: предметы приходят порциями, порядок задан дизайнером,
открытие — дофаминовый тик и контроль темпа сессии. Одновременно live 1–3 предмета
(скрины) — буфер сознательно мал: поиск не захлёбывается, внимание всегда имеет 2–3 цели,
не 30. Это ответ на наш кейс L40 v1 («13 открытых вёдер = арифметика без напряжения»):
маленький буфер работает даже там, где решения не соревнуются, — он управляет не сложностью
выбора, а плотностью нагрузки на поиск.

### 7.7 Что переносить / что не переносить в наш скелет
| Переносить | Не переносить |
|---|---|
| Порционную подачу (буфер 2–4 live-сущности) как клапан нагрузки | Отсутствие горлышка: прямая портировка даст З0-провал (решения не взаимодействуют) |
| Settle-петлю (snap+звук+частицы) как ритм награды 3–5 с | No-op-ошибку: в модели с ресурсом ошибка обязана менять состояние (З5) |
| «Сцена = полоса прогресса» (З6-предельная форма) | Ивент-кожу с таймером поверх релакс-ядра (слабость №5) |
| Окклюзионную топологию как источник `c_i` (в паре с реальным решением) | Контент-модель «каждый уровень = новая сцена» (себестоимость) |
| Скрытие цели как основную ставку (З4) — но с раскроем действием | |
| Семантику предметов как констрейнт-подсказку (нарратив, снижающий стоимость поиска) | |

**Синтез-гипотеза для Paint Loop v-next:** взять у Dreamy Room ПОДАЧУ и ФИДБЕК
(порции, settle-петля, сцена-прогресс, скрытая цель с раскроем действием), оставив у себя
ГОРЛЫШКО и ЦЕНУ ОШИБКИ (бак/лента, дефицит порций). Тогда процесс-ASMR станет обёрткой
темпа, а сложность останется decision-класса — то, чего у Dreamy Room нет и за что платит
её потолок в $7M против $189M у скелетов с горлышком.

Правило доминанты, читаемое по всем шести сценам: **комната = 1 доминантный оттенок +
1–2 акцента + дерево + крем**, доминанта чередуется от уровня к уровню (зелёная кофейня →
жёлтая кухня → лавандовый лофт → мятная спальня → терракотовая пекарня → розовая гримёрка).
Насыщенность растёт с «геройностью» сцены: ночная L787 (yt_sXMEF83yfAc) и тропический ивент
(yt_tlaf1ENEsNs) заметно сочнее комнатных уровней.

### 8.2 Форма-язык
- **Комната-лоток:** изометрическая диорама с двумя срезанными стенами; срез = толстая
  скруглённая кромка в цвет стены (торт-срез) — play1–6 единообразно.
- **Округлость тотальная:** острых углов нет ни у мебели, ни у еды, ни у маскотов; крупные
  радиусы, пухлые силуэты.
- **Единая обводка:** тёмно-шоколадный контур ≈2–3 px одинаковой толщины на всём —
  «стикерный» лук; маскоты нарисованы тем же предметным языком, что и мебель
  (кролик play2 читается как «ещё один предмет сцены»).
- **Одна лицевая деталь:** у каждого предмета одна крупная читаемая «морда» (носик крана,
  экран, дверца, носик чайника), развёрнутая в камеру — форма работает на З8.
- **Chibi-масштаб:** предметы укрупнены относительно комнаты (торт почти с табуретку,
  play5) — плотность сцены + читаемость мелочи с телефона.
- **Коробка = единственный «сырой» материал:** крафт со скотчем не перекрашивается ни в
  одной сцене — цветовой якорь игрового объекта в крашеном мире.

### 8.3 Шейдинг
- **Флэт-селл в 2 тона** на материал: база + тёмная полоса по нижней/боковой кромке;
  на крупных плоскостях (стены, плитка) — мягкий аэрографный градиент.
- **Блики точечные:** белые точки/полумесяцы на стекле, металле, глянцевой еде (торты,
  банки play1, play5); никакого общего блеска.
- **Тень = мягкий эллипс-блоб** под предметом; геометрических каст-шэдоу нет, свет
  ненаправленный.
- **Ноль текстур и шума:** «материя» передаётся плоскими паттернами — клетка, полоска,
  горошек (пледы play2, стены play3); чистая векторная заливка.
- **Окклюзия отрендерена материалом:** матовое стекло перегородки (play6) — бело-голубой
  градиент + белая кромка; тот же рецепт у витрины (play1) и воды ивента — стекло
  одновременно декор и механика скрытости.

### 8.4 Конструкция UI
- **Верхние ~8% экрана — весь HUD:** три «конфетные» пилюли на полупрозрачной подложке
  (itunes1–6): слева кнопка магазина (тёмно-бежевая капсула, белая иконка, локализованный
  лейбл), в центре бейдж уровня «0089» (танил/золото, тёмный номер), справа звёздная
  пилюля (кремовая, золотая звезда + счёт).
- **Кнопочный канон:** полный радиус, 2 тона (база + тёмная нижняя фаска), белая иконка,
  мягкая тень; тонких линий и рамок нет нигде.
- **Иерархия цветом:** мета-слой (магазин/уровень/звёзды) — десатурированные бежево-золотые;
  сцена — насыщенные. HUD приглушён, чтобы комната «выпрыгивала».
- **Ноль хрома в игровом поле:** ни кнопок, ни панелей ниже полосы HUD — всё поле отдано
  сцене, интерактивы только объектные.
- **Ивент-кожа** (yt_tlaf1ENEsNs): тот же пилюльный язык + прогресс-полоса с круглыми
  капами (зелёная заливка на сиреневом треке), таймер в сиреневой пилюле, 4 круглые
  розово-сиреневые кнопки бустеров с белыми иконками и счётчиками-бейджами, белая круглая
  пауза. Единственное место игры, где UI громче сцены.
- **Типографика:** округлый гротеск (класс Baloo/Fredoka); тёмно-коричневый текст на
  кремовом в мета-слое; бурсты «AMAZING!» — жирный дисплейный, белая заливка + толстый
  розовый контур, лёгкая дуга-наклон.

### 8.5 VFX-паттерны
- **4-лучевые белые искры** двух размеров, 3–6 шт. на экран, статичные с пульсом —
  маркер «полированного/интерактивного» (доска меню и фонарь play1, магниты play2).
- **Белое боке-песок** (мелкие точки) поверх всех сцен — один и тот же «напылённый» слой
  волшебства, часть фирменного фрейма.
- **Световой столб из открытой коробки:** конус тёплого бело-жёлтого прозрачного свечения
  вверх (play1, play5, play6) — attention funnel к источнику действия.
- **Live-предметы:** парение с покачиванием + мягкое гало + лёгкая пульсация масштаба
  (1–3 предмета над коробкой) — состояние «меня можно тащить» читается без слов.
- **Отпечатки лап на фоне** в цвет поля — фирменный фрейм-мотив, привязан к маскотам-питомцам.
- **Громкие VFX только в ивент-коже:** бурст «AMAZING!», наградные бейджи. В комнатных
  уровнях словарь эффектов на ~90% «тихий» (свечения, искры, столб) — визуальное
  продолжение контракта «не бьёт»; таймеры, энергия, красные бейджи в статике отсутствуют.

**Производственное следствие (из наблюдаемого, не домысел о процессе):** рецепт
«2-тональный флэт + единая обводка + паттерн вместо текстуры + чередование доминантного
оттенка» — это конвейерная формула: новая сцена уровня = та же геометрия предметов в новой
гамме и раскладке. Именно она позволяет держать 787+ уникальных комнат в одном стиле без
стилевого дрейфа (yt-коллаж L1–10 против play-скринов поздних уровней — стиль не плывёт).
