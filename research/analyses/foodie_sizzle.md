# Foodie Sizzle — разбор хита-референса

ABI GLOBAL LTD., пакет `com.abi.skewer.sort`. ~$8.4M / 22.9M загрузок, 4.6★ (21 991 оценок).
Веб-порта нет (CrazyGames, досье).
Источники: `research/screens/foodie_sizzle/DOSSIER.md`; 14 скринов глазами (play_shots ×4, itunes_shots ×6, yt_thumbs ×4);
`ontology/design_laws.md` (З0–З13, З-БУФЕР, З-МАСШТАБ); скелет-образец — `ontology/mechanics/paint_loop_concept.md`.

**В продукте задокументированы ДВЕ формы** — и это ключевой факт разбора:

| | Форма A — «Skewer Match» (2D, стор) | Форма B — «Gross Cooking ASMR» (3D, dev-сборка) |
|---|---|---|
| Где видно | itunes_shots 1–6, yt_thumbs ×4, стор-описание | play_shots ×4, watermark «Development Build» |
| Жанр | tap-to-match шампуров с таймером и заказами | процесс-ASMR варка gross-блюд, 3D лоуполи |
| Уровни | L3…L208+ (кадры) | не читается |
| Пакет/описание | стор-описание дословно про «Skewer Sort… match-3», пакет `com.abi.skewer.sort` | тот же листинг, название уже Foodie Sizzle — описание НЕ обновлено |

[inference: таймлайн пивота] Пакет и стор-описание называют «Skewer Sort» → форма A — исходный продукт; watermark
«Development Build» (характерный Unity-оверлей) в play_shots → форма B — следующая итерация на том же листинге.
Куди ушли $8.4M — по каким метрикам сделан разворот — из локальных материалов не видно; по директиве разбора
глубоко вскрывается скелет формы B, форма A разобрана как отгруженная оболочка.

## 1. Матмодель

### 1.1 Форма B — процесс-ASMR (ядро разбора)

**Состояние:**
- `step` — индекс текущего шага рецепта; рецепт = упорядоченная последовательность шагов-станций
  [inference: порядок не виден в статике, читается из смены станций между кадрами: выбор → крошение → налив → нанесение].
- `bowl` — чаша: {набор ингредиентов (мышь, тараканы, муравьи, 2 «кучки»), уровень жидкости h, цвет c, плавающие тела}.
  Уровень и цвет видны физически (specular-поверхность, shot4 красная, shot5 зелёная), тела плавают.
- `menu` — нижний док «Choose ingredient»: 4 карточки (мышь / кучка / таракан / муравьи), выбранная в красной рамке.
- `customer` — персонаж-приёмник: состояние поверхности (чёрные точки-прыщи) + нанесённый продукт (зелёная пена, shot6).
- HUD: НЕТ. Ни таймера, ни валют, ни прогресса, ни бустеров на всех 4 кадрах.

**Действия:**
- `choose_ingredient(m)` — тап по карточке; коммит в материю (ингредиент появляется в чаше).
- `manipulate(station)` — физическое действие станцией: pestle следует пальцу (крошение), банка наклоняется
  от drag и льёт струю с частицами (налив), пена наносится на лицо. Одно действие = непрерывный отклик материи.

**Ограничения:** из кадров НЕ читается ни одного: нет счётчиков, нет таймера, нет штрафных состояний.
[inference: ограничение только композиционное — состав и порядок шагов рецепта; выбор ингредиента внутри шага свободный]

**Горлышко (З2): ОТСУТСТВУЕТ.** Решения не соревнуются ни за один ресурс: ингредиенты не конкурируют за слот
(док без очереди), действия не тратят общий лимит. По З0 это «игра без модели»: провал не определён, функция
сложности от правил не растёт. Игра продаёт не сложность — sells плотность сенсорного отклика + валентность выбора.

**Победа/провал:** победа = рецепт собран → продукт нанесён/подан → гиперболизированная реакция персонажа.
Провал: не обнаружен ни в одном кадре [inference: отсутствует по построению].

**Функция сложности:** растёт ТОЛЬКО контентом: длина рецепта (число шагов), число станций (новые морфологии
действий), каталог gross-ингредиентов. Математической глубины 0 — это осознанный скелет «петли-впечатления».

### 1.2 Форма A — Skewer Match (стор, отгружена)

**Состояние:**
- Сетка грилей 3×3…3×4; гриль = до 3 шампуров (тип = набор из 3 ингредиентов) + белая тарелка-лоток снизу
  (держит 1–2 шампура в кадрах); состояния гриля/шампура: норма, заморозка (лёд-обёртка, itunes/shot4),
  «горячий» гриль (красное свечение, itunes/shot4), замок-кейс «Unlock» (yt M6P6, itunes/shot3).
- Таймер уровня: 02:41 (L8), 04:45 (L10), 02:34 (L208) — единственное давление.
- Заказы: медведи-клиенты сверху, пузырь заказа с типом шампура и квотой «0/12» (yt M6P6, правый кадр).
- Прогресс `served/total`: 2/15 (L3) … 18/44 (L8), 8/45 (L10), 14/42 (L208) — счёт ведётся в шампурах.
- Комбо-множитель ×5/×8/×10/×20 с полоской метра под ним (растёт от серий, падает в простое) [inference: механика комбо].
- Бустер-бар: 4 слота — пакет / красный вентилятор-сковорода / стопка тарелок (счётчик ×1) / шампур-инструмент
  (×2, закрыт до Lv.20); у каждого «+» = докупить.

**Действия:** `tap_skewer(s)` → шампур перелетает на тарелку под грилем (рукой-курсором показан тап, yt 69OG);
далее автоматика матча. Точная плумбинг матча из статики НЕ читается; две совместимые гипотезы:
[inference: (а) 3 одинаковых шампура на одной тарелке = подача; (б) тарелка = готовое блюдо, подаётся клиенту с квотой.
Кадры подтверждают полёт шампура в тарелку и квоты заказов, не критерий матча.]

**Ограничения:** время таймера; ёмкость тарелок; заморозки (шампур недоступен до разморозки); замки грилей
(открываются за прогресс/валюту [inference]).

**Горлышко (З2):** время × слоты тарелок. Все решения («какой тип собрать, что подать заказу 0/12»)
конкурируют за секунды и за приёмные слоты — честная классическая пара Tile Master-семейства.

**Победа/провал:** победа = весь total подан до нуля таймера (экран Win: сундук, монеты, 3 бустера-приза, itunes/shot6).
Провал = таймер вышел [inference: штрафная ветка не в кадрах; сердца ×5 в хабе — жизни/энергия сессии].

**Функция сложности:** размер сетки (3×3 → 3×4+), число типов шампуров, заморозки, локи, квоты заказов,
комбо-давление; хвост L200+ — та же морфология с плотной начинкой.

## 2. Кор-глагол + правила

### Форма B — ровно один кор-глагол на шаг: `manipulate_station`

Перед ним — выбор из меню, после — автоматика материи. В отличие от Paint Loop (тап = весь цикл), здесь цикл
трёхфазный: **выбор шага → физическое действие → результат-материя → реакция**.

| Не глагол | Почему |
|---|---|
| тап по чаше / клиенту | цель задаёт станция текущего шага, игрок цель не выбирает |
| drag камеры / зум | камера фиксирована во всех кадрах |
| счёт, обмен, покупка в уровне | HUD отсутствует, экономика вне ядра |
| откат / подсказка | не видны [inference: не существуют в петле-впечатлении] |

**Правила ядра (B):**
- П1 (выбор): док показывает 4 варианта; выбор коммитится в материю и обратной кнопки не имеет (необратим в пределах блюда) — мягкая форма З1.
- П2 (действие): манипулятор повторяет жест (пестик — давящие тапы, банка — наклон-налив); действие не засчитано, пока материя не ответила.
- П3 (материя): результат накапливается в чаше физически: уровень ↑, цвет = последний налитый, тела плавают.
- П4 (финал): продукт переносится на персонажа; реакция = payoff всего выбора (shot6: пена на прыщах).

### Форма A — кор-глагол: `tap_skewer`

| Не глагол | Почему |
|---|---|
| свайп/драг сбор | только одиночные тапы во всех кадрах |
| управление клиентами | заказы приходят сами, отменяются крестиком [inference: Х — скип заказа] |
| готовка шампуров | гриль-тайминг автоматичен [inference: свечение гриля = состояние готовки] |
| бустеры | мета-слой с покупкой «+», вне ядра |

**Правила ядра (A):** тап → шампур на тарелку → матч-автоматика → подача в заказ → комбо-метр тикает; таймер
неумолим; заморозка/замок блокируют доступ до раскрытия. Всё — стандарт поджанра, дифференциал только тематика.

## 3. UI/интерактив

**Форма B (dev-сборка) — экран-сцена без HUD:**
1. Стол + клеёнка-салфетка (сцена = 60% кадра); чаша-ступка в центре; сезонный реквизит по кромке
   (шампанское, бокал, свечи, гном в шапке Санты, ананас) — [inference: рождественский скин сцены].
2. Док «Choose ingredient»: 4 карточки на белом, выбранная — красная рамка. Универсальный паттерн
   «конечный док выбора» (канон Block Jam/Tile Master — З-БУФЕР), но без очереди прибытия.
3. Интерактив = прямой манипулятор: пестик и банка следует за пальцем, струю рвёт брызгами-частицами;
   жидкость — шейдер с уровнем и бликом, ингредиенты плавают телами. З8 в чистом виде: affordance читается
   из формы (банка наклоняется = «налей», пестик = «раздави»), ноль туториала.
4. Персонаж-приёмник: макро-дефекты (чёрные точки) = видимое состояние, которое продукт должен изменить
   (зелёная пена поверх точек, shot6) — прогресс записан НА ПЕРСОНАЖЕ, а не в полоске (З6).
5. 3D лоуполи: flat-шейдинг, сферо-композиция, насыщенная палитра; себестоимость сцены: 1 чаша + 4 ингредиента
   + 2–3 банки/пропа = бесконечный конвейер рецептов. Watermark «Development Build» [inference: Unity].

**Форма A (стор) — классический HUD-сэндвич:**
1. Верх: слева — уровень (Lv.N) + таймер + комбо-бейдж ×N с метром; справа — прогресс «14/42» и пауза/настройки.
2. Верхняя полоса клиентов (медведи с квотами) в поздних кадрах (L118) — заказы видны одновременно с полем.
3. Поле: сетка грилей, тарелки под ними, локи и морозы прямо в сетке.
4. Подвал: 4 бустера со счётчиками и «+» — монетизируемые кнопки внутри игрового экрана.
5. Мета-хаб (yt aDziivZP0xw): фасад ресторана = карта, кнопка «Level 7», сердца ×5, монеты 240+,
   ADS-кнопка с ТВ-иконкой, milestone-узлы «Level 10 / Level 20» с «!», нижние табы
   [inference: магазин / рейтинг / дом / соцсеть / закрытая фича]. Win-экран: сундук с монетами и бустерами.

## 4. Прогрессия/монетизация

**Форма A:** длинный ретейл-хвост L3→L208+ подтверждён кадрами. Прогрессия = плотность начинки (типы,
морозы, локи, квоты) при неизменной морфологии экрана. Монетизация (видимая): rewarded-кнопка ADS в хабе,
«+» на бустерах [inference: за монеты/ads], сундук-награда, сердца-энергия ×5, milestone-ивенты на L10/L20.
[inference: interstitial между уровнями — стандарт ABI-петли, в кадрах не виден.] Рейтинг 4.6 при
ads-агрессивном хабе — терпимая нагрузка. Профиль $8.4M/22.9M = ARPU ≈ $0.37 — массовый UA на дешёвом
удовлетворяющем CPI («шампуры стекают в тарелку») + длинный контентный хвост.

**Форма B:** контент-прогрессия = новые станции (ступка → налив → нанесение) и новые gross-каталоги;
[inference: длина рецепта растёт с уровнями]. Монетизация в кадрах отсутствует полностью — dev-сборка до
встраивания монет-слоя; для ABI типово: interstitial + rewarded на «следующий ингредиент/скип ожидания»
[inference]. Gross-out валентность (кучки, мыши, тараканы) — CPI-крючок, который НЕЛЬЗЯ показать в стор-шотах
(модерация) → креатив живёт на собственных видео-каналах, а стор-листинг остаётся «приличным» (форма A).
Это, вероятно, и есть причина держать обе формы на одном листинге [inference].

## 5. Сильные стороны по З1–З8

| Закон | Форма A (Skewer Match) | Форма B (Gross ASMR) |
|---|---|---|
| З0 модель | Есть: состояние/действия/ограничения/горлышко/победа записаны; провал = таймер | Формально провалена: нет ограничений, провала, функции сложности. Сознательная замена модели — сенсорной петлёй |
| З1 необратимость | Каждый тап = трата слота тарелки и секунды таймера между альтернативами | Мягкая: выбор ингредиента коммитится в материю блюда без отката |
| З2 горлышко | Время × слоты — все решения конкурируют честно | Нет. Игра выживает без него — значит скелет продаёт не конкуренцию решений (важный факт для нашего ядра) |
| З3 конечность+каскад | Таймер и слоты конечны → каскад «какой тип под заказ 0/12 взять первым» | Нет ресурса; каскад рождает только любопытство «что получится» |
| З4 скрытое=ставка | Морозы и локи раскрываются прогрессом; квота 0/12 планирует сбор | «Что сделает мышь с клиентом?» — раскрытие действием, но на план не влияет: любопытство вместо ставки |
| З5 ошибка=состояние | Промах съедает слот/время — давление, но нового состояния не рождает | «Ошибки» нет как категории: любой выбор = новое видимое состояние чаши/клиента (идеальная З5-поверхность без штрафа) |
| З6 полоска, не цифры | Прогресс 14/42 — число; слабое место | Уровень жидкости, цвет, пена, точки на лице — прогресс буквальной материей; эталонно |
| З7 топология, не декор | Перенесён поджанр целиком как топология (слоты/таймер/квоты) | Топология отсутствует; перенесена AV-петля жанра cooking-ASMR |
| З8 форма=функция | Шампур/тарелка/лёд читаются, но скупо | Пестик, банка, чаша, пена: механика читается из формы без слова; лучший слой игры |

Плюс вне законов: форма B — конвейерная себестоимость (одна чаша + реквизит = бесконечные рецепты) и
сезонный реквизит как скин-слой; форма A — milestone-ивенты и хаб, завязанные на уровень-номер (ретеншн-крючки без новой механики).

## 6. Слабости

1. **Расщепление продукта.** Две формы на одном листинге: стор-описание описывает игру, которой (уже) нет.
   Аудитория, Ashe и метрики двух несводимых ядер смешиваются — ABI платит за это конверсией страницы [inference: осознанная цена пивота].
2. **Форма B не имеет модели (З0).** Ноль ограничений → ноль напряжения → удержание держится только новизной
   станций. Потолок жанра: контент-конвейер и выгорание формулы (cooking-ASMR перенасыщен 2024–25).
3. **Форма A — клон без своей топологии.** Слоты+таймер+квоты = Tile Master-семейство в тематике шампуров;
   дифференциал не механический. Плумбинг матча непрозрачен даже из геймплея (две гипотезы в §1.2) — читаемость правил хромает.
4. **Таймер против обещания жанра.** Кухня-ASMR обещает релакс; форма A давит таймером, комбо-метром и
   сердцами — конфликт векторов по B6 (paint_loop §12): расслабляющая тема + соревновательное давление.
5. **Gross-out не проходит в стор-витрину.** Кучки/мыши в dev-скринах нельзя поставить в itunes_shots —
   витрина показывает старую форму → главный CPI-актив игры невидим в конверсии установки [inference].
6. **Подача ресурса залпом (форма B).** Док из 4 карточек без очереди прибытия: нет З-БУФЕР-давления,
   выбор мгновенно превращается в «посчитал и ткнул».
7. **Одна артерия в обеих формах.** A: всё поле обслуживает один поток подачи; B: одна чаша —
   single point of everything (З13 не нарушен только потому, что маршрутов нет вовсе).

## 7. КОРРЕЛЯЦИИ

### 7.1 Скелет
Форма B — чистый **скелет «процесс-ASMR»: выбор шага → физическое действие → результат-материя → реакция**.
Это расширение скелета S1 «Канва + Питатели» (paint_loop_concept.md) на три фазы: у Paint Loop тап по ведру —
сразу действие; у Foodie Sizzle перед действием стоит МЕНЮ ВАРИАНТОВ, а после результата — ПЕРСОНАЖ-реципиент.
Форма A — независимый скелет Tile Master (слоты + таймер + квоты), к форме B топологически не сводится:
пивот меняет скелет целиком, не материал. ABI доказал обе петли деньгами по отдельности.

### 7.2 Горлышко
Форма A: горлышко классическое — время × приёмные слоты. Форма B: горлышка НЕТ — и хит масштабируется.
Вывод для онтологии: **скелет process-ASMR монетизируется без З2, если валентность выбора (gross/юмор) и
плотность обратной связи компенсируют отсутствие конкуренции решений.** Но это подтверждает и обратное:
без горлышка продукт живёт скоростью контент-конвейера, а не глубиной — для нашего paint_loop горлышко
(бак крана) остаётся обязательным, если цель — глубина, а не viral-петля.

### 7.3 Обратная связь
Форма B — эталон плотности: каждое действие отдаёт 4 канала сразу — частицы, звук (sizzle/pour), уровень и
цвет материи, финальная трансформация персонажа. Уровень жидкости в чаше — буквально наш v4-кран (З6: два
жидкостных уровня зеркалят состояние). Реакция персонажа = отложенный payoff выбора, функциональный аналог
финального ревела Pixel Flow: эмоция в конце петли, держащая доливку следующего шага. Форма A даёт
полёт-в-тарелку + комбо-метр — плотность ниже, всё держит таймер.

### 7.4 Паттерны UI
- Док выбора из 4 карточек внизу с красной рамкой коммита (B) ↔ вёдра-питатели paint_loop ↔ dock Block Jam —
  один и тот же паттерн «конечный нижний док»; у Foodie Sizzle без очереди прибытия (упрощение).
- Прогресс: «N/M» шампуров вверху справа (A) — число-под-числом, слабо по З6; материя чаши и лицо клиента (B) — сильно по З6.
- Бустер-бар в подвале со счётчиками ×1–×3 и «+» — общий паттерн с Yarn Loop/hybrid-казуалками: монетизация в игровом экране.
- Хаб-фасад ресторана с milestone-узлами L10/L20 — прогрессия как путешествие по карте заведения; сердца+монеты+ADS слева-наверху — стандарт ABI.

### 7.5 Скрытая информация
Форма A: морозы/локи = скрытые ячейки, раскрываются действием/прогрессом — З4 в минимальной дозе, на план влияет слабо.
Форма B: выбор gross-ингредиента — скрытая ВЕТКА, а не скрытая ставка: «что будет?» раскрывается действием
(аналог «?»-вёдер paint_loop §6), но исход не бьёт по ресурсам — любопытство вместо риска. Для нашего ядра
урок: скрытая информация работает и без штрафа, если payoff — реакция мира, а не исправление ошибки.

### 7.6 Подача ресурса
Форма B: ингредиенты подаются доком на 4 слота — конечный буфер выбора (пол-шага к З-БУФЕР), но без очереди
прибытия и дефицита; «ресурс» — сами варианты, и он не конкурирует. Форма A: грили = порционная подача
(по 3 шампура), морозы и локи = очередь разблокировки — З-БУФЕР соблюдён в каждой клетке поля.
Формула для нас: подавать выбор порциями (док) — обе формы; подавать РЕСУРС порциями с очередью — только A.

### 7.7 Пивот-дифф ABI: что сохраняется при смене скелета на том же листинге

| Слой | Форма A (Skewer Match) | Форма B (Gross ASMR) | Вывод |
|---|---|---|---|
| Пакет/листинг | `com.abi.skewer.sort` | тот же | **инсталл-база и ASO сохраняются при полной смене ядра** |
| Стор-описание | про «Skewer Sort match-3» | не обновлено | текст листинга — расходный материал, ядро продукта не защищает |
| Кор-глагол | tap_skewer | manipulate_station | заменён полностью |
| Горлышко | время × слоты | нет | заменён тип петли: конкуренция → впечатление |
| Валентность | «вкусно/уютно» (медведи, гриль) | «фу/ха-ха» (мышь, кучки, прыщи) | эмоциональная ось сменена на противоположную — CPI-крючок новый |
| Монетизация | ads+бустеры+сердца | отсутствует в dev-сборке [inference] | монет-слой пристраивается ПОСЛЕ проверки петли |

**Формула пивота:** скелет и валентность меняются целиком; неизменны пакет, сеттинг «еда» и конвейерная
себестоимость контента. Риск — расщепление витрины (§6.1, §6.5).

---

### Вывод для нашего ядра
1. Скелет «выбор → физическое действие → материя → реакция» формы B — брать как СЛОЙ подачи и обратной связи:
   меню-док выбора перед действием и персонаж/мир-реципиент после результата усиливают paint_loop без ущерба горлышку.
2. Форма B доказывает допустимость петли без горлышка только для viral-казуалок с контент-конвейером;
   для продукта, целящегося в глубину (наш кран v4), горлышко и дефицит остаются обязательными — иначе З0-теорема пустоты.
3. Уровень жидкости/цвета как единственный индикатор состояния (чаша, пена, лицо) — прямое подтверждение З6/З8;
   числа в HUD (14/42 формы A) — антипример.
4. Gross-out валентность выбора — дешёвый (арт-стоимость нулевая: те же мешы) и мощный CPI-слой, но витринно-ограниченный:
   закладывать «приличный» альтернативный сет для стор-скринов заранее.

## 8. Дизайн ассетов (vision-разбор по просмотренным скринам)

описывается только видимое, домыслов о пайплайне нет.

### 8.1 Палитра — 8 опорных цветов

| # | Свотч | Где снято | Роль |
|---|---|---|---|
| 1 | `#F09030` → `#F0A830` (янтарь) | стол формы B, shot3 | основная «еда-тепло»: стол, дерево, свечи; насыщенность ~S204 при V240 — цвет кричит, но не кислит |

цвета разведена по насыщенности, а не по тону. `#F0D8C0`-крем и белый — единственные «неедовые» поверхности.

### 8.2 Форма-язык

- **Форма B — сфероиды и капсулы, ноль кромок.** Чаша = полусфера, пестик = вытянутая капсула, ингредиенты =
  свёрнутые ленты и сферы, пена = кластер надувшихся сфер, гном/ананас = конус+сфера. Радиусы скруглений
  максимальны везде, где форма позволяет; острая геометрия отсутствует вовсе. Bubble-типографика
  («Choose ingredient»): жирные круглые литеры с толстой тёмной обводкой — текст работает как стикер, читается на любом фоне.
- **Форма A — модульные rounded-rect и вертикальные стопки.** Всё поле собрано из скруглённых прямоугольников
  (гриль = тёмный rounded-rect с внутренней решёткой, тарелка = светлая плашка под ним, бейджи/кнопки = pill).
  Еда — вертикальные стопки из 3 сегментов на палочке: тип шампура читается по цвету сегментов с расстояния,
  это и есть форма-носитель данных. Персонажи (медведи, капибара) — круглые головы, черты-точки, крупные шапки.
- **Константа обеих форм:** иерархия «крупный объект — мелкий реквизит» и чибри-пропорции живых существ;
  ни в одном кадре нет тонких линий, острых углов и мелкого декора — плотность детали падает к краям кадра.

### 8.3 Шейдинг и материалы

- **Форма B:** мягкий ламберт по сферам (не жёсткий флэт — градиент объёма виден на чаше и пестике) + один
  направленный источник; тени — мягкие blob-пятна под объектами, без резких проекций. Жидкость: насыщенная
  диффузия + широкие белые specular-блики на поверхности (shot4/shot5) — «мокрость» сделана бликом, не прозрачностью.
  Материальные дифференциаторы: камень = крапчатый шум, стекло бутылок = полупрозрачность с бликом, дерево =
  планки с вариацией тона, пена = матовая (блика нет — по глине/пене/жидкости три разных ответа поверхности).
- **Форма A:** чистый вектор-флэт с 2-тоновым шейдингом: база + одна тень на 15–20% темнее (нижняя половина
  формы) + точечный белый глянец. Обводок у еды нет — глубину даёт тёмная подложка гриля. Градиенты только в
  фонах хаба (закат: персик `#F0A890` → крем `#F0C090`); игровой экран — плоский.
- **Общий принцип:** читаемость держится на КОНТРАСТЕ ЯРКОСТИ (светлая еда на тёмном гриле, белый док на
  оранжевом столе), а не на обводках и не на эффектах.

### 8.4 Конструкция UI

- **Форма B — сцена = интерфейс.** Из HUD есть ровно один элемент: нижний полупрозрачный док с 4 белыми
  карточками ~квадратного пропорциона, серо-голубая обводка, выбранный вариант — толстая розово-красная рамка
  (единственный акцентный цвет UI). Заголовок bubble-текстом. Всё состояние (уровень жидкости, цвет, содержимое)
  показано самой 3D-материей — UI-хрома почти нет (З6 в предельной форме).
- **Форма A — 4-полосный сэндвич:** (1) статус-полоса: слева бейдж уровня + таймер жирными цифрами с тёмной
  обводкой + чип комбо «x8» с заполняющимся жёлтым метром, справа прогресс «18/44» с иконкой и пауза;
  (2) полоса клиентов с квотами (поздние уровни); (3) сетка 3×N грилей с тарелками-подвесами; (4) бустер-бар:
  4 белых круга со счётчиками и зелёными «+». Один экран = одна CTA, вторичные элементы в 2–3 раза мельче.
- **Хаб (форма A):** полноэкранная иллюстрация-фасад, единственная крупная зелёная кнопка «Level 7»
  (заливка + обводка темнее на тон), валютные пилюли по углам (сердца/монеты с зелёным «+»), ADS-чип,
  milestone-узлы с красными «!», нижний таб-бар с одной активной вкладкой (оранжевая HOME).
- **Семантика цветов UI, одинаковая в обеих формах:** зелёный = подтвердить/добавить, красный = отмена/опасность
  (крестик на заказе, ADS), жёлтый = валюта/награда, белый = нейтральная поверхность, розово-красная рамка = текущий выбор.

### 8.5 VFX-паттерны

- **Форма B — VFX как продолжение материала.** Струя = сужающаяся лента цвета жидкости; удар о поверхность =
  радиальный разлёт сфероидов ТОГО ЖЕ цвета (красный налив → красно-розовые брызги shot4; зелёный → зелёная
  шипучка shot5); в объёме жидкости поднимаются пузырьки (жёлтые в зелени) и плавают капли-сферы в воздухе;
  пена = разросшийся кластер сфер. Ни вспышек, ни колец, ни экранных постэффектов — вся энергия остаётся
  внутри материи, поэтому результат действия остаётся НА ЭКРАНЕ как состояние (брызги не исчезают, а подпитывают уровень).
- **Форма A — VFX как вектор внимания.** Полёт шампура в тарелку по дуге; белая контурная подсветка тап-таргета
  в туториале (yt 69OG); красное свечение состояния гриля; конфетти-дождь + монетный фонтан с вращением монет
  + radial-лучи за сундуком на Win (itunes shot6). Комбо — заполняющаяся полоска без частиц.
- **Общий закон VFX игры:** частица наследует цвет источника и живёт в мировом слое (не поверх UI);
  экранного bloom/виньетки нет ни в одном из 14 кадров. Дорогой вид — анимация состояния, дешёвый — оверлей.

### 8.6 Что переносить в наши ассеты
1. Палитра-контракт: тёплая съедобная база + приборные тёмные + РОВНО ОДИН неон-резерв под аномалию (у них — лайм зелья);
   красный разводить на 3 регистра насыщенностью.
2. Двух-тоновый флэт для 2D и ламберт+specular-блик для жидкостей — читаемость без обводок через яркостный контраст подложек.
3. VFX-правило «частица = цвет источника, живёт в материи»: результат действия остаётся видимым состоянием, а не исчезающей искрой (З8).
4. Сцена-как-интерфейс (форма B): минимум хрома, выбор в одном доке с одной акцентной рамкой — прямой кандидат в наш игровой экран.
